# Feedback System · UX Research

React 19, Vite 6, Tailwind CSS 4. Минималистичный отчёт с боковой навигацией и адаптивными таблицами. Результаты не заполнены: все таблицы показывают по три нейтральных плейсхолдера. Они не обозначают реальных респондентов или объём выборки.

## Запуск и проверка

Node.js 22 или совместимая более новая версия.

```sh
npm ci
npm run dev
npm test
npm run build
```

## Наполнение данными

- `src/data/overview.js` — вводный текст и период проведения.
- `src/data/respondents.js` — пользователи VoC: `respondents`, поля `id`, `role`, `tasks`, `usage`, `needs`, `details`.
- `src/data/reportTables.js` — схемы и пустые массивы `records` для потребностей, ограничений, сценариев и рекомендаций.
- `src/data/research.js` — порядок страниц и описания разделов. Старая база результатов очищена.

Записи в `records` должны иметь уникальный `id`, значения колонок по их `key`, `role` либо массив `roles` и объект `details` по ключам схемы. Несколько записей одной роли поддерживаются: идентификатор записи не связан с ролью. После наполнения список ролей формируется автоматически. Плейсхолдеры заменяются записями и не включаются в категории.

Подробности поддерживают текст, массивы, а также объекты цитат и ссылок с полями `quote`, `url`, `label`, `locator`. Используйте HTTPS-ссылки с корректными правами доступа. Не размещайте закрытые интервью или личные данные на публичном сайте. Данные статического сайта доступны посетителям.

Для ограничений поле `kind`: `tool` (инструмент) либо `process` (рабочий процесс). `significance` заполняется только после анализа последствий, частоты и влияния на решения. Не предполагайте, что любое ограничение решается изменением Feedback System.

Для сценариев поле `kind`: `existing` (существующая практика) либо `potential` (гипотеза). Будущие записи визуально различаются сплошной и пунктирной рамкой. Ожидаемая польза не равнозначна подтверждённой потребности.

Для рекомендаций поле `category`: `supported`, `revision`, `validation` (названия в `recommendationCategories`). Категории пока не присвоены. Отделяйте результаты интервью от предложений команды, требующих проверки. Детали должны объяснять основание рекомендации и предлагаемые действия.

Не добавляйте вымышленные потребности, цитаты, выводы или показатели. Компоненты при постепенном наполнении менять не требуется.

## GitHub и Netlify

GitHub Actions выполняет тесты и production-сборку. `netlify.toml` задаёт `npm run build`, публикацию `dist`, Node.js 22 и SPA fallback. Подключите репозиторий в Netlify; дальнейшие push в `main` могут запускать автоматическую публикацию.
